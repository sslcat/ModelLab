# Training dependencies and security

The historical worker and its [original package pins](../remote/requirements.txt) are part of the experimental record. The pilot, rank and model-size draft generators check their archived worker hashes before a run. Those drafts retain the original packages, model revisions and training options. Their exact direct pins are available for traceability. Installation today can still resolve different transitive packages from those captured in the [session evidence](../evidence/README.md).

Ordinary new jobs stage the [current dependency profile](../remote/current/requirements.txt) with its [worker](../remote/current/train.py). The job configuration identifies the profile and records the staged file hashes. It uses the pinned RunPod image with PyTorch 2.8 and CUDA 12.8. The current worker uses TRL’s cumulative token counter to calculate throughput and omits a legacy Transformers training argument that has been removed. This profile has not run a GPU smoke test or reproduced any historical result. The published findings come entirely from the frozen studies.

A Linux Python 3.12 metadata resolution with Torch 2.8.0 selected 66 packages. The current direct profile returned zero known vulnerabilities in that audit. The full metadata audit reported nine IDs against Torch 2.8.0, the package still supplied by the pinned image.

## Nine advisories in the historical profile

| Advisory | Historical affected path and applicability | Mitigation |
| --- | --- | --- |
| [PYSEC-2025-217](https://osv.dev/vulnerability/PYSEC-2025-217) | Transformers X-CLIP checkpoint conversion can deserialize untrusted data. The receipt worker uses causal language models and never runs the converter. | Avoid third-party conversion scripts and serialized checkpoints. The current Transformers pin is outside the reported range. |
| [PYSEC-2025-218](https://osv.dev/vulnerability/PYSEC-2025-218) | Transformers GLM4 deserialization. The registered Qwen and Mistral models do not use the GLM4 loader. | Keep the model allowlist and require safetensors for base weights. The current pin is outside the reported range. |
| [PYSEC-2026-2288](https://osv.dev/vulnerability/PYSEC-2026-2288) | Trainer RNG state deserialization during checkpoint resume on affected Torch versions. These workers start fresh, and the image supplies Torch 2.8. | Do not resume from untrusted checkpoints. The current pin is outside the reported range. |
| [PYSEC-2026-2289](https://osv.dev/vulnerability/PYSEC-2026-2289) | Untrusted model configuration can bypass remote-code consent through the attention implementation. A model-load operation is part of the worker. The historical path only loads allowlisted, revision-pinned repositories. | Use the current pin. Retain revision verification and `trust_remote_code=False`. |
| [PYSEC-2026-2290](https://osv.dev/vulnerability/PYSEC-2026-2290) | LightGlue model initialization can override the remote-code setting from serialized configuration. The receipt worker does not instantiate LightGlue. | Keep model types on the allowlist. The current pin is outside the reported range. |
| [PYSEC-2026-3929](https://osv.dev/vulnerability/PYSEC-2026-3929) | Tokenizer or processor export can write outside the destination when template names come from an untrusted model. The worker saves artifacts and loads metadata only from the pinned Hub sources. | Use the current pin. Keep loaded tokenizer sources allowlisted and immutable. |
| [PYSEC-2026-4174](https://osv.dev/vulnerability/PYSEC-2026-4174) | Custom generation can download Python before obtaining consent. The worker uses standard generation and supplies no custom-generation code or repository. The record lists 5.8.1 as the last affected version and names no fixed version. | Keep custom generation disabled and use only reviewed snapshots. The current pin is outside the reported range. |
| [PYSEC-2026-3804](https://osv.dev/vulnerability/PYSEC-2026-3804) | Accelerate can follow unsafe shard paths in hostile checkpoint indexes. Model loading uses device placement and may read sharded weights. | Use the current Accelerate pin and only trusted, revision-pinned model metadata and shards. |
| [PYSEC-2026-3716](https://osv.dev/vulnerability/PYSEC-2026-3716) | Datasets folder builders can read outside the dataset directory based on hostile metadata. ## Image-provided PyTorch

The [new profile](../remote/current/requirements.txt) keeps the existing CUDA image. Its PyTorch 2.8.0 metadata audit still reported:

- Checkpoint or PT2 deserialization ([PYSEC-2026-1856](https://osv.dev/vulnerability/PYSEC-2026-1856), [PYSEC-2026-2286](https://osv.dev/vulnerability/PYSEC-2026-2286), [PYSEC-2026-139](https://osv.dev/vulnerability/PYSEC-2026-139)). The worker uses safetensors and starts new runs from pinned model revisions. Keep third-party serialized checkpoints and PT2 archives out of the workspace.
- Tensor operations ([PYSEC-2025-203](https://osv.dev/vulnerability/PYSEC-2025-203), [PYSEC-2025-204](https://osv.dev/vulnerability/PYSEC-2025-204), [PYSEC-2025-206](https://osv.dev/vulnerability/PYSEC-2025-206)). ModelLab does not accept arbitrary tensor operations through its dataset interface. Review and test a newer compatible GPU image before running user-supplied model code or workloads.
- JIT and recurrent-network operations ([PYSEC-2025-193](https://osv.dev/vulnerability/PYSEC-2025-193), [PYSEC-2025-194](https://osv.dev/vulnerability/PYSEC-2025-194), [PYSEC-2025-195](https://osv.dev/vulnerability/PYSEC-2025-195)). The scanner reports these for the 2.8.0 pin. The advisory descriptions refer to PyTorch 2.6.0 and the ModelLab receipt worker does not directly invoke these APIs.

A historical rerun still installs the affected versions. Run it only on a disposable pod with the registered model revisions and synthetic inputs. Keep personal credentials and unrelated files off the pod, and review the account inventory and deadlines before authorizing a rerun. The public read-only app and CPU-only tests do not install the GPU packages. For new GPU work, audit the full resolved environment and pinned container, including the packages supplied by the image. Direct-pin review cannot establish the security of transitive packages or the operating system.
